Desain Basis Data Relasional — ERD → LRS
Aplikasi Absensi Wajah SMK Jaya Buana

Dokumen ini menyajikan perancangan basis data relasional aplikasi absensi siswa berbasis pengenalan wajah SMK Jaya Buana, mulai dari Entity Relationship Diagram (ERD), proses transformasi ERD ke LRS, Logical Record Structure (LRS) final, hingga spesifikasi basis data. Semua kode PlantUML berada di dalam tag <pre class='plantuml'> agar dapat di-render manual.

1. Entity Relationship Diagram (ERD)

Domain aplikasi terdiri atas lima entitas. Admin adalah akun pengelola terminal. Kelas menampung banyak Siswa (relasi one-to-many). Setiap Siswa memiliki banyak catatan Absensi harian (one-to-many). Pengaturan adalah entitas konfigurasi terminal yang bersifat key-value dan berdiri sendiri. Tidak terdapat relasi many-to-many pada domain ini.

2. Transformasi ERD ke LRS (Logical Record Structure)

Transformasi dilakukan dengan kaidah baku berikut:

  • Relasi one-to-many KELAS → SISWA: foreign key ditempatkan di sisi many. Maka tabel SISWA memperoleh kolom kelas_id yang mereferensi KELAS.id.
  • Relasi one-to-many SISWA → ABSENSI: foreign key ditempatkan di sisi many. Maka tabel ABSENSI memperoleh kolom siswa_id yang mereferensi SISWA.id. Pasangan (siswa_id, tanggal) dijadikan kunci unik agar satu siswa hanya punya satu baris absensi per hari.
  • Tidak ada relasi many-to-many, sehingga tidak diperlukan tabel junction.
  • Tidak ada weak entity, seluruh entitas memiliki primary key tunggal sendiri.
  • Atribut multivalue: vektor wajah disimpan sebagai satu kolom embedding bertipe BLOB (serialisasi 192 float), sehingga tidak dipecah menjadi tabel terpisah. Begitu pula PENGATURAN yang dimodelkan sebagai tabel key-value tunggal.
  • Entitas ADMIN dan PENGATURAN tidak memiliki relasi, ditransformasikan menjadi tabel mandiri tanpa foreign key.

Hasil transformasi: lima entitas ERD menjadi lima tabel LRS — admin, kelas, siswa, absensi, dan pengaturan — dengan dua foreign key (siswa.kelas_id dan absensi.siswa_id).

@startuml
title Transformasi ERD ke LRS - Absensi Wajah SMK Jaya Buana

class "admin" <<Table>> {
  + PK id : INTEGER
  - username : TEXT
  - pin_hash : TEXT
  - created_at : TEXT
}

class "kelas" <<Table>> {
  + PK id : INTEGER
  - nama : TEXT
  - created_at : TEXT
}

class "siswa" <<Table>> {
  + PK id : INTEGER
  # FK kelas_id : INTEGER
  - nama : TEXT
  - nis : TEXT
  - photo_path : TEXT
  - embedding : BLOB
  - is_draft : INTEGER
  - created_at : TEXT
}

class "absensi" <<Table>> {
  + PK id : INTEGER
  # FK siswa_id : INTEGER
  - tanggal : TEXT
  - check_in_time : TEXT
  - check_out_time : TEXT
  - status : TEXT
  - auto_checkout : INTEGER
}

class "pengaturan" <<Table>> {
  + PK key : TEXT
  - value : TEXT
}

note bottom of siswa : FK kelas_id hasil transformasi\nrelasi 1-N KELAS -> SISWA
note bottom of absensi : FK siswa_id hasil transformasi\nrelasi 1-N SISWA -> ABSENSI

siswa --> kelas : kelas_id
absensi --> siswa : siswa_id
@enduml

3. Logical Record Structure (LRS) — Final

LRS final di bawah ini adalah skema logis bersih hasil transformasi, tanpa anotasi proses. Struktur ini konsisten 100% dengan ERD dan Spesifikasi Basis Data.

@startuml
title LRS Final - Aplikasi Absensi Wajah SMK Jaya Buana

class "admin" <<Table>> {
  + PK id : INTEGER
  - username : TEXT
  - pin_hash : TEXT
  - created_at : TEXT
}

class "kelas" <<Table>> {
  + PK id : INTEGER
  - nama : TEXT
  - created_at : TEXT
}

class "siswa" <<Table>> {
  + PK id : INTEGER
  # FK kelas_id : INTEGER
  - nama : TEXT
  - nis : TEXT
  - photo_path : TEXT
  - embedding : BLOB
  - is_draft : INTEGER
  - created_at : TEXT
}

class "absensi" <<Table>> {
  + PK id : INTEGER
  # FK siswa_id : INTEGER
  - tanggal : TEXT
  - check_in_time : TEXT
  - check_out_time : TEXT
  - status : TEXT
  - auto_checkout : INTEGER
}

class "pengaturan" <<Table>> {
  + PK key : TEXT
  - value : TEXT
}

kelas "1" --> "0..*" siswa : memiliki
siswa "1" --> "0..*" absensi : mencatat
@enduml
